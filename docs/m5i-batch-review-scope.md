# M5i — 按 M5g 批次筛选本地 4:5 审核队列

M5h 已提供原生 4:5 本地审核队列，直接复用 M5e 的状态计算与旧 UI 人工标注控件；M5i **不再新建队列或审核数据库**，只解决多个历史试验混在一起时难以定位本轮 20 个 SKU 的问题。

## 使用方法

1. 通过 M5g 完成 `--apply` 导入（不是只有预检）。默认输出目录 `data/eval_runs/m5g_import/`。
2. 本机以 `uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000` 启动，访问 <http://127.0.0.1:8000/>。
3. 在「本地 4:5 验收队列」点击「仅看 M5g 批次」旁的文件选择器，选择 `data/eval_runs/m5g_import/batch_import_results.json`。
4. 再点「刷新本地验收队列」。只显示导入结果里对应的海报，标题前显示 SKU；点击「打开审核」，继续使用原有 4:5 预览、人工标注与手动 PaddleOCR。
5. 点击「清除批次筛选」回到全量本地队列。浏览器刷新页面后也需要重新选文件，避免不小心把上次批次当作当前批次。

## 安全和正确性

- 使用浏览器 `file.text()` **本地读取 JSON，不把文件 POST 到服务端**，也不上传真实商品图片。文件里仅抽取 `sku_id → poster_id` 供当前页面内存筛选。
- 仅接受 `schema_version=m5g-1`、`mode=apply`、1–100 个 SKU、有规范 SHA-256 与合法 ID 的记录；拒绝重复海报 ID、缺损数据、超出 200 KB 的文件。
- 使用 `textContent` 而不是插入未经转义的 HTML；SKU 与标题只能作为文本呈现。
- 仍通过现有只读 `GET /api/trials/review-queue` 获取真实验收状态，队列被筛选不等于评分数据也被筛选。**M5e 的 `--score` 当前仍会评测同一审核员下全部符合条件的本地版本**，不得将它当成本批次专属成绩。
- 若导入结果中的某个 ID 不存在于当前 `POSTER_DATA_DIR`，页面会显示缺少的数量，不默默声称全部已审核。
- 应用尚无登录、鉴权、多租户和真正的样本同意/来源认证，切勿直接公网部署。审核员代号不能构成个人身份验证。
- 预览与审核仍读取实际海报最新版本；旧导入 v1 的海报若修改为 v2，队列会显示最新 v2，而不是把旧人工标签当成新版审核。

## 验证

```bash
uv run --locked python -m pytest -q tests/test_batch_review_scope.py tests/test_trial_review_queue.py
```

测试覆盖：通过 M5g 真实本地导入 API 生成对应批次结果、能在 M5h 审核队列定位海报、浏览器本地文件和格式校验入口、不可注入的文字渲染，以及 Node 可用时的内联 JavaScript 语法检查。测试依旧采用合成商品图，不会执行 OCR、收费模型或真实运营图片。
